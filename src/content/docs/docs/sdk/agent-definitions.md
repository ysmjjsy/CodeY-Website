---
title: Agent 定义与会话
description: AgentDefinition 的不可变修订、提供商配置、运行快照、会话与幂等语义。
---

AgentDefinition 是一个逻辑名称加不可变修订。每次更新都会创建一个新修订。会话固定一个定义修订、默认值、组件修订和事件投影版本。已存在的会话在创建后永不追随 `latest`。

## 提供商配置与凭据

创建定义之前，先通过 `client.providers.put()` 存储提供商配置，通过 `client.credentials.put()` 存储密钥。配置包含公开的提供商 / 模型 / Base URL 和请求默认值。定义引用返回的配置 ID 和凭据 ID。

- 配置更新只影响之后解析的会话；已接收的运行保留其冻结的配置和凭据代次。
- 删除配置会阻止新会话解析引用它的定义，但不会改写历史快照。

## 运行快照

运行被接收时，守护进程在执行前持久化一条 `ResolvedAgentSnapshotRecord`。它包含生效的模型选项、组件哈希、策略交集、限额和凭据代次引用。密钥值只在守护进程内解析，从不进入快照或事件。

运行覆盖（override）可以收窄权限、工具和预算，但不能突破运行时、应用或定义的上限。更新凭据会创建新代次；吊销优先于固定的代次。

## 会话操作

- `query()` 原子地创建会话、绑定快照并入队第一条输入。
- `createSession()` 创建空闲会话。
- `Session.send()` 追加另一次运行。
- Fork 创建新身份和历史链接，但不复制活跃的权限、问题或运行。

## 幂等

幂等键的作用域是应用加操作。用相同的规范化输入重复请求会返回原始身份；用相同的键提交不同输入会返回 `idempotency_conflict`。

## 事件

Agent 事件是语义投影，不是原始 TaskStore 事件。游标是不透明字符串。客户端加载历史、从最近应用的游标继续、按事件 ID 去重，并且只在终止事件之后才产出结果。
