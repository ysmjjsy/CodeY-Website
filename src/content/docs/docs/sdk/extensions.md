## 附着回调

附着回调使用专用的、经过认证的双工连接。工具和 Hook 注册需要声明作用域、JSON Schema、超时、结果预算、并发、风险和幂等性。守护进程持有授权、Schema 校验、租约过期、取消、输出脱敏和持久化调用状态。

- 客户端、会话和运行作用域是精确的。两个活跃宿主不能认领同一个工具作用域。
- 前置工具 Hook 和会改变结果的 Hook 必须 fail-closed，并声明 `mayChangeResult`。
- Hook 响应可以拒绝或收窄工作，但不能授予权限。

## 持久化扩展 sidecar

附着回调只在宿主进程和心跳存活期间可用，对自动化和已分离的 Agent 无效。需要持久化的 Node / Python sidecar 时，使用 `@codey/agent-extension-sdk` 或 `codey-agent-extension-sdk`。

已安装的 sidecar 会被复制进守护进程持有的内容寻址存储，经过哈希、信任和沙箱处理后才被使用。

## 权限与问题处理

权限和 AskUserQuestion 请求以 AgentEvent 形式到达。配置的处理器通过同一持久化 broker 修订解决请求。缺失的处理器遵循定义的交互回退策略——**缺失从不意味着批准**。

## 凭据边界

- 凭据 API 只在写入时接受密钥值，读取返回元数据。
- 生产环境支持操作系统凭据后端和显式选择的仅属主可读文件后端。
- 密钥被排除在 AgentDefinition、回调、事件、日志、错误和诊断信息之外。

## 信任模型

所有回调输入都必须视为不可信。回调不继承对守护进程存储或凭据的直接访问。联网工具始终受网络代理和工作区策略约束。
