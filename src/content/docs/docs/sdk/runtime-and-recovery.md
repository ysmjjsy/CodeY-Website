## 应用隔离

每个 `application_id` 映射到相互隔离的数据、配置、组件、日志、令牌和本地端点路径。这个 ID 必须跨版本保持稳定。SDK 和运行时版本严格成对；清单的目标、大小、SHA-256、存储范围和特性图会在启动前校验。

发布产物带签名。离线或企业分发场景下，设置 `CODEY_RUNTIME_TRUSTED_PUBLIC_KEY` 为 PEM 公钥，让校验固定到你的分发权威。包管理器完整性保护官方平台包；显式传入的 `runtime_path` 必须始终携带匹配的清单和签名。

## 附着模式与持久模式

**附着模式**在没有可达的兼容实例时启动一个子运行时。只要客户端、运行、浏览器进程、回调或调度器义务持有活动租约，守护进程就保持存活；空闲超时后可以退出。

**持久模式**是显式的。`RuntimeManager.persistentService()` / `persistent_service()` 通过 launchd、systemd 用户服务或 Windows 任务计划安装一个带版本的用户单元。服务持有日志、重启失败的运行时进程并禁用空闲退出。安装、状态、启动、停止和卸载是相互独立的操作。

## 定时自动化

自动化要求持久模式。它固定一个 AgentDefinition 修订、时区、间隔和 misfire 策略：

- `run_once` 最多补发一次追赶运行；
- `skip` 直接推进持久化游标。

依赖附着回调的定义会被拒绝，因为宿主进程可能不在场。

## 崩溃恢复

TaskStore 是已接收命令、会话、快照、事件和恢复状态的事实来源。守护进程崩溃后可以重放确定性操作。外部副作用不是 exactly-once：工具调用携带幂等身份；结局未知的外部调用进入 `recovery_required`，必须被显式解决。

## 并行升级

运行时升级是并行（side-by-side）的：停止并 drain 旧服务，安装匹配的新产物，然后启动。旧运行时无法打开超出其声明存储 Schema 范围的数据。

Drain 会拒绝新运行，并等待活跃工作、回调调用、浏览器进程和调度器义务释放活动租约。仍有阻塞者时升级必须停止；不能替换使用中的运行时目录。

## 浏览器组件

可选的浏览器组件独立于基础运行时。其清单固定运行时范围、平台、Node 版本、Chrome 构建和哈希：

- `disabled`：从不解析；
- `optional`：缺失时报告能力不可用；
- `required`：校验失败时启动失败。
