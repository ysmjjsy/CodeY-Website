title: 受控执行与安全
description: CodeY 的能力边界与安全模型：权限模式、沙箱、网络代理与用户批准。
---

CodeY 的安全模型建立在一个前提上：Agent 工作在守护进程中运行，而不是在 UI 中。每一次运行都由权限、沙箱、工作区和网络策略共同约束。

## 能力与安全边界

- Agent 工作在守护进程中运行，不在 UI 中。
- 运行设置组合了权限模式、访问范围和工具能力过滤器。
- 工具发起的 HTTP 流量必须通过守护进程持有的网络代理。
- 工作区和文件系统适配器拒绝不安全的路径穿越和符号链接越界。
- MCP Server、Skill、Plugin、浏览器自动化和电脑操作始终受守护进程策略约束。
- 敏感或结局不确定的操作可以暂停，等待用户显式批准。
- 电脑操作只通过当前平台可用的原生运行时进行，并受操作系统权限约束。

## 运行模式

| 模式 | 说明 |
| --- | --- |
| 安全 | 最保守的约束组合，适合不受信任的任务 |
| 标准 | 日常开发的默认平衡 |
| 完全访问 | 有意移除部分操作系统沙箱，**仅用于受信任的任务** |
| 自定义 | 按需组合权限、访问范围与工具能力过滤器 |

## 密钥处理

- 凭据 API 只在写入时接受密钥值，读取只返回元数据。
- 密钥值只在守护进程内部解析，从不进入 AgentDefinition、回调、事件、日志、错误或诊断信息。
- 生产环境支持操作系统凭据后端，以及显式选择的仅属主可读的文件后端。

## 漏洞报告

安全漏洞请遵循[支持与安全策略](/docs/support/)中的流程报告，不要在公开 Issue 中披露利用细节。
