CodeY 是通过 GitHub 仓库维护的预发布软件。

## 在哪里提问

- 可复现的 Bug：使用 [Bug 报告表单](https://github.com/ysmjjsy/CodeY/issues/new?template=bug_report.yml)。
- 聚焦的功能请求：使用[功能请求表单](https://github.com/ysmjjsy/CodeY/issues/new?template=feature_request.yml)。
- 开发问题：开一个 Issue，描述代码区域、目标和已尝试的检查。
- 安全漏洞：遵循下方[安全策略](#安全策略)，不要在普通 Issue 中发布利用细节。

提问前，先搜索既有 Issue，并阅读[文档](/docs/intro/)与[贡献指南](/docs/contributing/)。

## 报告应包含的信息

- CodeY 版本或 commit SHA
- 操作系统和架构、安装方式
- 从源码构建时的 Node.js、pnpm、Rust 版本
- 模型提供商和协议（不含凭据）
- 确切的步骤和期望行为
- 相关日志、截图或最小复现仓库
- 重启 CodeY 后问题是否仍然存在

附加日志或截图前，移除 API 密钥、访问令牌、私有文件内容、个人数据和专有提示词。

## 支持范围

项目不提供响应时间保证。模型提供商的通用故障、账单争议，以及仅存在于第三方 MCP Server 或 Plugin 的缺陷，请向相应提供方或项目报告。

## 安全策略

CodeY 处于 `0.1.x` 预发布开发阶段，安全修复应用于当前 `main` 分支。

**不要在公开 Issue 中披露利用细节、凭据、私有数据或概念验证代码。**

本仓库暂未启用私密漏洞报告。申请私密报告渠道：

1. 提交一个[安全联系请求](https://github.com/ysmjjsy/CodeY/issues/new?template=security_contact.yml)，只包含受影响的组件和私密跟进请求。
2. 不要在这个公开请求中包含复现步骤或技术细节。
3. 等维护者建立私密渠道后，再分享敏感信息。

有价值的私密报告包含：受影响的 commit、版本和平台；受影响的组件和信任边界；前置条件和可复现步骤；影响和现实攻击场景；安全可分享时的概念验证；已知的缓解建议。

涉及以下边界的报告尤其有用：守护进程本地 IPC 认证或隔离、权限决策或批准绕过、沙箱 / 工作区 / 文件系统 / 符号链接逃逸、网络代理或本地端口策略绕过、密钥存储 / 脱敏 / 凭据暴露、Plugin / Skill / MCP / 浏览器 / 扩展信任校验、电脑操作授权或保护模式逃逸、运行时产物签名或更新校验、会重复有害外部副作用的任务恢复。

仅存在于上游依赖的漏洞先报给对应项目；当 CodeY 对该依赖的使用构成独立利用路径或需要协调发布时，也在这里报告。
